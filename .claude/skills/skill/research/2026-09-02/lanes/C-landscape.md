# Automated text-space optimization for agent skills and harnesses

**Research cutoff: 2026-09-02.** Repository status was checked on that date. “Not found” means no public paper, benchmark, code, star count, or dated commit was located. Evidence is author-reported unless explicitly called independent.

## Executive finding

Microsoft [SkillOpt](https://arxiv.org/abs/2605.23904) remains the strongest general baseline: bounded trajectory-driven edits, explicit train/validation separation, rollback, seven target models, and direct evaluation in Claude Code and Codex. Its 2026-07 release also added [SkillOpt-Sleep integrations](https://github.com/microsoft/SkillOpt/blob/main/plugins/README.md) that mine real sessions and stage validated `CLAUDE.md` or `SKILL.md` changes.

The most serious alternatives divide into four groups:

1. **GEPA and GEPA-derived systems**, broader and more extensible than SkillOpt.
2. **Skill-library evolution systems**, better at creating, routing, pruning, and composing many skills.
3. **Harness and workflow optimizers**, capable of changing code, control flow, tools, or agent architecture.
4. **Native Claude/Codex evaluation tools**, practical but mostly evaluators, not full optimization loops.

# A. Taxonomy

Codes: **S/L/H** = single artifact, library, harness; **V/J/P/N** = programmatic verifier, LLM judge, paired contrast, no reliable gate; **B/G/E/C/D** = bounded edits, textual gradient, evolutionary/Pareto, curate/generate, diagnosis only; **O/R** = offline batch or online/nightly real sessions; **T/X/Both** = text, executable code/harness, or both.

| Placement | Systems |
|---|---|
| **S, V, B, O, T** | SkillOpt; SkillOpt research mode; CodexOpt gated engine; Anthropic trigger-description optimizer |
| **S, J or V, E, O, T** | GEPA; DSPy GEPA; gskill; SkillMOO; OPRO; PromptBreeder |
| **S, J or V, G, O, T** | SkillGrad; TextGrad |
| **S, P+V, B, O, T** | SkillAudit; Anthropic skill-creator body loop |
| **L, V/J, C or E, O, T/Both** | SkillBrew; SkillsVote offline; Trace2Skill; EvoSkill; EvoSkills; Ace-Skill; Workflow-to-Skill; MUSE-Autoskill; Skills-Coach |
| **L, J/reward, C, R, T/Both** | Memento-Skills; SkillsVote online; ACE; SkillOS |
| **L, V, B, R, T** | SkillOpt-Sleep; `vinnylarouge/skill-opt-skill`; gbrain SkillOpt integration |
| **H, V/J, E, O, Both** | Meta-Harness; GEPA `optimize_anything`; Hermes self-evolution; jramos agent-self-evolution; EvoAgentX optimizers |
| **H, V, B/C, R, X/Both** | Karpathy autoresearch; Qoder Quest; MiniMax M2.7 self-evolution |
| **Diagnosis/scoring only** | SkillCoach rubrics; `claude plugin eval`; `/skill-doctor`; Claude Agent SDK evals; Codex `plugin-eval`; OpenAI Evals |
| **Deployment/local-model variants** | `dspy-agent-skills`; mitkox/SkillOpt; official Claude/Codex SkillOpt plugins |

The biggest strategic distinction is not “gradient versus evolution.” It is whether the evaluator exposes real causal feedback. SkillOpt’s bounded edits work because failures, edits, and held-out acceptance are separated. GEPA’s larger search space wins when evaluator traces are rich enough to justify larger mutations.

# B. Tasks without an automatic verifier

The evidence is promising but not yet sufficient to claim that automated optimization of copy, UX, research judgment, or open-ended SOP quality reliably avoids Goodhart’s law.

| Approach | Judge design and evidence | Goodhart assessment |
|---|---|---|
| **SkillAudit** | Same-task with/without-skill contrast, multiple process evaluators, passage-level attribution, and a fixed structural constraint checker. It achieved 73.9 average reward across eight professional domains without using hidden outcomes during evolution. | Best published design because the skill must improve behavior relative to its own counterfactual and cannot move the constraint boundary. The final reported reward still came from benchmark tasks, not pure taste. |
| **Anthropic skill-creator** | Explicit baseline/ablation arm, assertion evidence, optional independent blind comparator, and human artifact viewer. | Strong practical design for content and UX. No large published study showing resistance to judge gaming. |
| **GEPA with an LLM judge** | Any pairwise or scalar judge can be used and full textual feedback becomes actionable side information. GEPA’s strongest published gains are still mostly executable or objective benchmarks. | Mechanically capable, but safety comes from evaluator design, not GEPA itself. |
| **SkillCoach and Skills-Coach** | Process rubrics are separated from outcome verification; Skills-Coach generates diverse tasks and traceable criteria before comparative execution. | Better than one final holistic score, but self-generated tasks, rubrics, and revisions can share blind spots. |
| **vinnylarouge wrapper** | Reports ρ=0.868 between its judge and a checker, but only on 16 examples. | Useful smoke test, not convincing general evidence. |
| **Observed failure mode** | A 2026 community study of 92 skill A/B evals reported self-grading inflated scores by as much as 60 points ([BuidlGuidl, 2026](https://buidlguidl.com/blog/evaluating-agent-skills)). | Direct warning against letting the proposing model define, execute, and grade the same rubric. |

For qualitative work, the minimum credible loop is:

1. Freeze the rubric and negative constraints before optimization.
2. Use a with/without or old/new blind pairwise comparison.
3. Hold out tasks and use a judge model different from the proposer.
4. Require evidence citations to source material or trajectory spans.
5. Mix LLM judgment with deterministic checks for omissions, forbidden claims, structure, cost, and latency.
6. Human-audit random wins and all large score jumps.
7. Periodically replace synthetic cases with real user sessions and complaints.

No reviewed system has yet demonstrated robust, independent, long-horizon non-Goodhart optimization for pure brand voice, copy taste, UX quality, or research insight. That result is **not found**.

# C. The three systems to try first

| Rank | Recommendation | Why |
|---|---|---|
| **1** | **Microsoft SkillOpt-Sleep plus the main SkillOpt trainer** | It already runs against both Claude Code and Codex, can use subscription-friendly handoff, harvests real sessions, stages rather than silently applies changes, and has the strongest held-out evidence. Start with one high-frequency `SKILL.md` or `CLAUDE.md`, not the whole library. |
| **2** | **GEPA `optimize_anything`, using its Claude Code plugin** | It is the best choice for Gemini/OpenRouter keys, arbitrary SOPs, subagent prompts, tool descriptions, workflow text, and eventually harness code. The official example explicitly uses `openrouter/google/gemini-3-flash-preview`, and Claude Code plus Codex can discover the supplied skill. Use frozen pairwise graders for qualitative workflows. |
| **3** | **EvoSkill** | It is the strongest deployable option for creating and improving complete multi-file skills, not merely editing one Markdown body. It supports Claude Code, Codex CLI, and OpenRouter directly, and has real Claude Code benchmark evidence. Use CodexOpt instead when the immediate target is specifically `AGENTS.md` and you want the smallest Codex-only setup. |

The practical stack is therefore: **SkillOpt for conservative nightly refinement, GEPA for flexible experiments and non-coding SOPs, EvoSkill for skill-library and multi-file package evolution.**
