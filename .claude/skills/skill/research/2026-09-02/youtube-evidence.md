## Conflicts and corrections

- Gradient framing. iSPwNmsa7kA is titled "Microsoft Found Gradient Descent for AI Agent Skills" and builds the explainer on skills-as-weights [00:06-01:10]. Corrected in-thread by @markburton5318 (13 likes): no gradient exists, this is non-gradient optimization.
- Novelty. @bonquaviusdingle5720 on iSPwNmsa7kA says DSPy did this four years ago; @chougaghil on the same video asks why DSPy GEPA is absent from the harness benchmark section.
- More rules vs fewer rules. Almost every REGURGITATION video frames the value as adding learned rules. MqPHm_6zZBQ [20:03-21:30] contradicts it: Eugene Yan reports halving prompt size and deleting prescriptive steps gave the largest production gains, and [56:46-57:25] gives a 500-line memory file collapsed to three words. eM2qQUIm_lk [05:00-05:50] reaches the same pruning conclusion from the paper's own 1-4 accepted edits.
- Optimize vs replace with code. MqPHm_6zZBQ [40:40-44:12] argues deterministic tasks (regex, rigid spreadsheet extraction) should be promoted to CLI tools or MCPs, directly against the SpreadsheetBench headline most videos lead with.
- Optimizer quality. iSPwNmsa7kA [05:45-05:52] says the optimizer needs a frontier model. lj8Mpk2GoCo [05:50-06:25], citing SkillLens, says execution power does not predict extraction power. SdX0nX9mXgs [23:45-25:55] shows the concrete failure: an oracle curator (Gemini-2.5-Pro) writing for a Qwen3-8B executor degraded performance through the capability gap.
- Cross-harness transfer size. Reported three ways with no reconciliation: +59.7 SpreadsheetBench Codex to Claude Code (enNcCVo1T64 [06:55], OXEq_1tstJ0 [06:54-07:23], ieD359Bs8Y0 [06:33-07:06]); +31.8 same direction (aVW-KG4sDdo [19:17-19:58], Izbt-JmVmCQ [09:01-09:15], xJrUbLtiZwg [15:40-16:44]); +29.4 average (JUBMDTCiM0M [01:26]).
- Codex-trained beats Claude-Code-trained. 78cDurifNGM [03:28-05:35] reports a Codex-trained SpreadsheetBench skill scoring 81.8 inside Claude Code, above Claude Code's own in-domain 80.4. No other video discusses it.
- Overfitting stance. -wA36Nnz0d4 [11:18-11:49] flags benchmark overfitting as the key risk, while enNcCVo1T64, ZYC86mBNtrA, OXEq_1tstJ0, h_8YXLfiK90, ksZqvVGTW5I and 86_LUP699Bs list no SkillOpt weakness at all.
- Graphify's headline number. @SulsaCikkectuve corrects "up to 70x" to about 2.5x (~80k vs ~200k). Also contradicted by @jason_v12345 (59 likes) citing Boris Cherny that Claude Code dropped indexing for grep, @DonatoEspera (185 likes) noting IDEs already keep ASTs, and first-hand negatives (@James-ln6li no improvement, @curiousgeorge7515 few tokens saved, @matthewwoodard9810 graph goes obsolete immediately).
- Daytona credibility. The report rates 8VC5q_64USo high credibility on live terminal logs; @jackbauer322 disputes it: "22 minutes of emptiness and can't see shit, no concrete examples".
- Post-session hook. NWlQCDWxzLs [40:00-40:30] proposes one. Corrected by @lxiebq4cx7-0zc4lez2oj: you cannot know when a session ends, only a per-turn hook is possible.
- Paper identity. ogIlO9YmsLM covers "SkillOpt-Lite: Better and Faster Agent Self-Evolution via One Line of Vibe"; the report's wrapper flags it as a different paper, not confirmed to be 2605.23904.
- Reward hacking, empirical. SdX0nX9mXgs [20:50-21:20] found that without a length penalty, curators degenerate into copying raw trajectories verbatim into markdown. X4dEHRzBLmc [37:40] found the counter-intuitive opposite of expected seeding: handing the model the full policy upfront trapped it in a local minimum, a minimal seed learned better.

## Gaps

Nothing in the 65 videos covers:

- Any SkillOpt run against a Claude Code or Codex subscription. The one real run (yj17Fvyr09s) uses local vLLM Qwen3.5-4B through the Azure OpenAI compatibility shim. Every SkillOpt dollar or token figure quoted anywhere in the corpus comes from the paper, not from a bill.
- Any independent reproduction of any SkillOpt benchmark number. W5OTRXKySaM [04:50-04:56] and voApGrmYO6Q [04:37-04:47] both note the numbers are Microsoft's own; nobody re-ran them.
- Sleep mode or any idle-time SkillOpt operation in use. lj8Mpk2GoCo [06:31-07:21] mentions a speculative "SkillOpt-Sleep" from an announcement only. MetaClaw's idle-time LoRA is the nearest thing and is a different system.
- Non-coding SOP optimization with a measured result. Many videos propose targets (marketing, HR onboarding, legal letters, support triage, medical translation, lecture transcripts, business manuals) and OYXjZLX2kv4 [63:35-67:35] gives a rubric weighting, but no before/after number on any non-coding, non-benchmark SOP appears anywhere.
- Multi-skill or whole-library optimization with SkillOpt. Named as a limitation three times, never attempted. SkillOS and Hermes Curator address it, SkillOpt does not.
- CLAUDE.md or AGENTS.md optimized by SkillOpt itself. eM2qQUIm_lk [07:34-07:44] applies the philosophy by hand; codexopt is the only tool actually run against AGENTS.md and it uses GEPA.
- Any SkillOpt run past 1 epoch shown on screen, any convergence curve, any third-party wall-clock measurement, or any dollar receipt.
- A SkillOpt vs GEPA or DSPy comparison run by anyone other than the SkillOpt authors. @chougaghil asks for exactly this on iSPwNmsa7kA and gets no answer.
- SkillOpt v0.2.0 release contents, the 2026-07-02 tag, or any commit after the paper.
- Cost or operation of the prescribed security mitigations. nnDAaPpXgOY establishes 21/21 configs produce unsafe skills and prescribes lifecycle governance, but no video runs or prices such a loop.
- Human-in-the-loop acceptance rates: what fraction of SkillOpt-accepted edits a human reviewer would also accept.
- Cross-platform validity of an optimized skill (Mac vs Windows), asked by @tstfam on yj17Fvyr09s, unanswered.
